# v2.1.0 — 2026-05-18

## 概述

`v2.1.0` 是一次 **minor 级能力增强发布**，核心目标是把 `capture` 从“仅 `query / params` 局部支持显式全量”升级为“`headers / query / params / body` 四类输入统一支持显式全量 + 规则对象控制”，以真正支撑请求复现 / replay 增强场景。

本版本的重点包括：

- `headers / query / params / body` 四类输入都可显式开启全量模式；
- 引入统一规则对象：`mode / fields / exclude / sensitiveKeys / maxValueLength / maxDepth / maxItems / snapshot / output`；
- `body` 支持递归叶子展开、数组上限控制与可选原始快照；
- 保持现有白名单写法和快捷写法兼容；
- README、类型、core 实现、测试与发布验证同步收口。

> ⚠️ 本次是公开能力扩展，因此版本级别按 **minor** 处理；但当前运行时依赖仍沿用 `2.0.2` 中为 Docker / 私有源兼容性临时回退的 `@opentelemetry/auto-instrumentations-node@0.72.0`，发布时应继续附带该已知风险说明。

---

## Added

- `capture.headers` / `capture.body` 新增显式全量模式支持，与 `query / params` 的能力边界对齐。
- 新增统一规则对象 `CaptureSourceOptions`，支持：
  - `mode`
  - `fields`
  - `exclude`
  - `sensitiveKeys`
  - `maxValueLength`
  - `maxDepth`
  - `maxItems`
  - `snapshot`
  - `output`
- `body` 全量模式新增递归叶子展开能力，可生成 `http.request.body.*` 形式的可检索属性。
- 新增 `request.headers.raw` / `request.query.raw` / `request.params.raw` / `request.body.raw` 快照输出能力（由 `snapshot` / `output` 控制）。
- 新增 `maxItems` 护栏，用于限制 body 大数组展开数量。
- 新增 `output: "attributes" | "snapshot" | "both"`，用于区分普通观测模式与复现增强模式。

---

## Changed

- `RequestCaptureOptions` 已统一改为四类输入共享 `CaptureInput` 模型。
- `src/core/http-core.ts` 的 capture 归一化与采集逻辑已重构，以统一处理：
  - 显式全量
  - 白名单字段
  - 排除规则
  - 敏感字段脱敏
  - 深度与数组数量限制
  - 展开属性 / 快照输出控制
- `README.md` 的 capture 章节已改写为新口径：
  - 不再声明 `headers / body` “不支持全量”
  - 明确默认保守策略
  - 增加规则对象说明
  - 增加普通观测模式 / 复现模式示例
- 相关核心测试与适配器测试已同步更新，覆盖新的全量与规则语义。

---

## Fixed

- 修复此前 `headers / body` 只能白名单采集、无法满足请求复现场景的问题。
- 修复 body 全量模式下缺少数组规模控制的设计缺口，避免大数组导致 attributes 膨胀。
- 修复复现增强场景中“只能展开属性、无法显式控制快照输出”的能力缺口。

## Notes

  1. `git commit`
  2. `git tag v2.1.0`
