# v2.1.11

Released: 2026-06-11

## Fixed

- VextJS auto preload now defers full SDK/exporter startup to plugin setup by default, so `app.config.otel.enabled=false` and `opentelemetryPlugin({ enabled: false })` can prevent real SDK/exporter startup.
- `package.json` `vext.otel.enabled=false`, `VEXT_OTEL_DISABLED=1`, `VEXT_OTEL_PRELOAD=0`, and `OTEL_SDK_DISABLED=true` now short-circuit preload before loading the full OpenTelemetry SDK.

## Added

- Added package-level `vext.otel.preloadSdk=true` and `VEXT_OTEL_FORCE_SDK=1` opt-ins for applications that explicitly need earliest-process SDK / auto-instrumentation startup.

## Security

- Upgraded `@opentelemetry/auto-instrumentations-node` to `0.76.0` to remove the nested vulnerable Prometheus exporter / SDK audit chain.
- Upgraded dev-only `vitest` and `hono` patch versions to clear release-blocking high/critical audit findings.

## Compatibility

- No public API or export path was removed.
- Existing VextJS applications that require earliest-process OTel SDK startup should set `package.json` `vext.otel.preloadSdk=true` or `VEXT_OTEL_FORCE_SDK=1`.
- Non-Vext manual `node --import vextjs-opentelemetry/instrumentation ...` usage still starts the SDK when an effective endpoint or auto-instrumentation signal is present.
