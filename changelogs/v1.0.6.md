# v1.0.6 — 2026-05-14

## 兼容性与文档收口修复

### 概述

本版本围绕 `v1.0.5` 之后的兼容性与文档收口问题做补丁修复：在保持公开 API 不变的前提下，补齐异常路径 span name 与路由模板的一致性，完善顶层 `CHANGELOG.md` 的版本索引结构与 `README.md` 的目录导航，并纠正文档中关于 Egg/Koa 专属回调和 `initOtel()` 初始化路径的两处矩阵误差。同时将发布前验证链路与新增 `lateAttributes` 能力一起纳入 `1.0.6` 的正式发布说明。

---

### Fixed

- 异常路径现在会与成功路径一样，使用解析后的路由模板更新 span name。
- `README.md` 的框架差异表已纠正：
  - `onCtxInit` / `onRequestDone` 仅为 Egg 专属能力，不再误写为 Koa 也支持；
  - `Express / Hono / Fastify` 不再误写为直接通过 `initOtel()` 初始化 exporter，而是明确为“应用侧自行初始化 SDK”。
- 顶层 `CHANGELOG.md` 已切换为版本总览索引优先的结构，便于快速浏览发布历史。

---

### Added

- `README.md` 新增目录导航。
- `README.md` 新增“兼容性与升级建议”章节，明确说明：
  - `chat` / `user` / `payment` 这类通过 `/koa` 子路径 `initOtel()` 接入的服务，升级到 `1.0.6` 在代码层面仍兼容；
  - Node.js 运行时仍需满足包声明的 `>=18`。

### Compatibility Notes

当前仓库内已确认的消费方式：

- `chat/app/otel-init.cjs`
- `user/app/otel-init.cjs`
- `payment/app/otel-init.cjs`

三者都通过 `require("vextjs-opentelemetry/koa")` 调用 `initOtel()`，这一入口在 `1.0.6` 中保持不变，因此**升级到 `1.0.6` 无需修改接入代码**。

唯一需要额外确认的是运行环境：

- 包声明仍要求 `Node.js >= 18`
- 若这些服务实际仍运行在 Node 16，则这不是 `1.0.6` 新引入的问题，但依然不属于受支持环境

### Known Notes

- `chat` / `user` / `payment` 的服务 `package.json` 目前仍声明 `engines.node >=16`，与 `vextjs-opentelemetry` 自身的 `>=18` 存在口径差异；若后续希望把升级说明完全收口，建议同步抬高这些服务的 engines 声明或在部署规范中明确运行时基线。
