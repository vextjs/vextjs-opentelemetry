# v2.0.0 — 2026-05-14

## v2.0.1 — 2026-05-15

### 概述

`v2.0.1` 是一次 **patch 级质量收口发布**，核心目标是把上一轮新增的声明式 `capture` 能力补齐到真正可发布状态：

- 支持 `query / params` 的显式全量模式（`true` / `"*"`）；
- 保持 `headers / body` 仍为白名单采集；
- 修复 `Koa / Egg` 在 `end-phase` 不重取晚到 `params/body` 的缺口；
- 同步补齐 README、回归测试与发布验证。

---

### Added

- `capture.query` / `capture.params` 新增显式全量模式：
  - `true`
  - `"*"`
- `HttpObservationContext` 明确承载统一的 `query / params / body` 字段。
- 新增 Koa / Egg “晚到字段”回归测试，覆盖 `next()` 后才可得的 `params/body` 场景。

---

### Changed

- `README.md` 新增声明式 `capture` 章节，明确：
  - `query / params` 可显式全量采集
  - `headers / body` 仍保持白名单
  - Hono 仅从 `bodyCache` 读取 body 的设计边界
- `Koa` 适配器在 end/error 阶段统一重建 `HttpObservationContext`，重新读取 `query / params / body`。
- `EggContextLike` 类型补齐 `query / params`，使类型层与运行时事实一致。
- 开发依赖中的 `fastify` 与 `hono` 已升级到无当前已知直系 CVE 的版本，用于清理发布前安全告警。
- 运行时依赖中的 `@opentelemetry/sdk-node` 与 `@opentelemetry/auto-instrumentations-node` 已升级到安全版本，同时同步刷新锁文件中的 OTLP / protobuf 依赖链。
- 开发联调依赖 `vextjs` 已对齐到 `^0.3.5`，与当前主仓发布版本保持一致。

---

### Fixed

- 修复 `Koa / Egg` 中 `params/body` 仅在 start 阶段快照、导致晚到字段无法被 `capture` 拿到的问题。
- 修复 README 中若干 TypeScript 代码块不完整导致的文档校验噪音。

## 统一公开配置模型（Breaking Change）

### 概述

`v2.0.0` 是一次 **major 级 API 收敛发布**。

本版本的核心目标不是继续为不同框架维持不同公开配置心智，而是将 `vextjs-opentelemetry` 真正收敛为一个**通用观测模块**：

- 不同框架可以保留不同的加载 / 注册方式；
- 但用户侧配置对象必须统一；
- 旧的混合模型（`extraAttributes` / `lateAttributes` / `customLabels` / `onCtxInit` / `onRequestDone` / 顶层 `onEnd`）不再作为主公开接口保留。

---

### Breaking Changes

#### 统一配置字段

以下旧字段不再作为主公开接口使用：

- `tracing.extraAttributes`
- `tracing.lateAttributes`
- `metrics.customLabels`
- 顶层 `onEnd`
- Egg 专属 `onCtxInit`
- Egg 专属 `onRequestDone`

统一替换为：

- `tracing.startAttributes`
- `tracing.endAttributes`
- `metrics.labels`
- `lifecycle.onStart`
- `lifecycle.onEnd`

#### 统一用户心智

所有 HTTP 适配器现在共享同一套配置模型：

- VextJS
- Koa
- Egg.js
- Express
- Hono
- Fastify

框架差异只体现在：

- SDK 初始化方式
- 中间件 / plugin 注册方式
- `raw` 参数的具体类型

而不再体现在配置字段命名上。

---

### Added

- 新增统一的 `HttpObservationContext` 类型，显式区分：
  - `phase: "start"`
  - `phase: "end"`
- 新增统一的 lifecycle hook 模型：
  - `lifecycle.onStart`
  - `lifecycle.onEnd`
- `metrics.labels` 支持与 tracing 同样的统一回调签名，可读取 phase-aware ctx 和 raw 对象。

---

### Changed

- Core HTTP 处理链重构为统一的 `start / end` phase 模型。
- 所有适配器统一接入 `startAttributes / endAttributes / metrics.labels / lifecycle`。
- VextJS 插件配置不再保留与通用适配器不同命名的长期语义。
- README 全面改写为统一配置模型主线。
- 工作区内自家消费项目（`admin` / `chat` / `user` / `payment`）已同步迁移到新字段。

---

### Removed

- 旧配置字段作为主公开 API 的继续使用说明。
- README 中关于 Egg 专属公开 hook 的主推荐文档路径。

---

### Migration Guide

#### 1. tracing

```ts
// before
const beforeTracing = {
  tracing: {
    extraAttributes: undefined,
    lateAttributes: undefined,
  },
};

// after
const afterTracing = {
  tracing: {
    startAttributes: undefined,
    endAttributes: undefined,
  },
};
```

#### 2. metrics

```ts
// before
const beforeMetrics = {
  metrics: {
    customLabels: undefined,
  },
};

// after
const afterMetrics = {
  metrics: {
    labels: undefined,
  },
};
```

#### 3. lifecycle / side effects

```ts
// before
const beforeLifecycle = {
  onEnd: undefined,
  // Egg only:
  onCtxInit: undefined,
  onRequestDone: undefined,
};

// after
const afterLifecycle = {
  lifecycle: {
    onStart: undefined,
    onEnd: undefined,
  },
};
```

#### 4. Egg.js / Koa 业务字段回写

以前常放在：

- `onCtxInit`
- `onRequestDone`

现在统一迁到：

- `lifecycle.onStart`
- `lifecycle.onEnd`
