# v2.0.0 — 2026-05-14

## 统一公开配置模型（Breaking Change）

### 概述

`v2.0.0` 是一次 **major 级 API 收敛发布**。

本版本的核心目标不是继续为不同框架维持不同公开配置心智，而是将 `vextjs-opentelemetry` 真正收敛为一个**通用观测模块**：

- 不同框架可以保留不同的加载 / 注册方式；
- 但用户侧配置对象必须统一；
- 旧的混合模型（`extraAttributes` / `lateAttributes` / `customLabels` / `onCtxInit` / `onRequestDone` / 顶层 `onEnd`）不再作为主公开接口保留。

---

### Breaking Changes

#### 统一配置字段

以下旧字段不再作为主公开接口使用：

- `tracing.extraAttributes`
- `tracing.lateAttributes`
- `metrics.customLabels`
- 顶层 `onEnd`
- Egg 专属 `onCtxInit`
- Egg 专属 `onRequestDone`

统一替换为：

- `tracing.startAttributes`
- `tracing.endAttributes`
- `metrics.labels`
- `lifecycle.onStart`
- `lifecycle.onEnd`

#### 统一用户心智

所有 HTTP 适配器现在共享同一套配置模型：

- VextJS
- Koa
- Egg.js
- Express
- Hono
- Fastify

框架差异只体现在：

- SDK 初始化方式
- 中间件 / plugin 注册方式
- `raw` 参数的具体类型

而不再体现在配置字段命名上。

---

### Added

- 新增统一的 `HttpObservationContext` 类型，显式区分：
  - `phase: "start"`
  - `phase: "end"`
- 新增统一的 lifecycle hook 模型：
  - `lifecycle.onStart`
  - `lifecycle.onEnd`
- `metrics.labels` 支持与 tracing 同样的统一回调签名，可读取 phase-aware ctx 和 raw 对象。

---

### Changed

- Core HTTP 处理链重构为统一的 `start / end` phase 模型。
- 所有适配器统一接入 `startAttributes / endAttributes / metrics.labels / lifecycle`。
- VextJS 插件配置不再保留与通用适配器不同命名的长期语义。
- README 全面改写为统一配置模型主线。
- 工作区内自家消费项目（`admin` / `chat` / `user` / `payment`）已同步迁移到新字段。

---

### Removed

- 旧配置字段作为主公开 API 的继续使用说明。
- README 中关于 Egg 专属公开 hook 的主推荐文档路径。

---

### Migration Guide

#### 1. tracing

```ts
// before
tracing: {
  extraAttributes: ...,
  lateAttributes: ...,
}

// after
tracing: {
  startAttributes: ...,
  endAttributes: ...,
}
```

#### 2. metrics

```ts
// before
metrics: {
  customLabels: ...,
}

// after
metrics: {
  labels: ...,
}
```

#### 3. lifecycle / side effects

```ts
// before
onEnd: ...
// Egg only:
onCtxInit: ...
onRequestDone: ...

// after
lifecycle: {
  onStart: ...,
  onEnd: ...,
}
```

#### 4. Egg.js / Koa 业务字段回写

以前常放在：

- `onCtxInit`
- `onRequestDone`

现在统一迁到：

- `lifecycle.onStart`
- `lifecycle.onEnd`
